# Rufus survey for Sirius Flash

Source: `pbatard/rufus` @ `3e696ab` (2026-10-15). `ChangeLog.txt` head is **4.15 (2026-06-30)**, `rufus.loc` is v4.14.
(depth 50). All `path:line` citations are relative to that clone root. Nothing from the tree was built or run.
What I did run, all on data: `7z l/x` and `bsdtar -t` on `res/uefi/uefi-ntfs.img` and `res/loc/test/*.iso`, `osslsigncode verify`
on an extracted `.efi`, and a ~60-line Python Authenticode/DBX parser (`scratchpad/scripts/pe256_dbx.py`, run with `-I`).
Sirius files were only read, never written. Items marked *(code)* in the Sirius column come from reading `crates/core/src/lib.rs`,
not from PROJECT-STATE/README.

Licence baseline: Rufus's own files are GPL-3.0-or-later (`LICENSE.txt`, per-file headers such as `src/format.c:5-9`), so adapting them is fine for a GPL-3.0 project as long as copyright notices stay; vendored third-party parts keep their own licences (called out below).

Already recorded in PROJECT-STATE and not repeated: the accepted-format list, bled, UEFI:NTFS-by-default and its dead `MSG_129`,
ms-sys blob provenance, the MBR behaviour (keypress prompt, 0x81 masquerade as a fact about the blobs), `needs_boot_code()`.

## Summary

* Rufus is a Windows GUI whose real value is a large body of **hard-won rules**: what to scan in an image (§3), what to refuse or warn about before touching a disk (§2, §8), how to lay out partitions (§4f), and how to survive Windows' caching (§2 steps 6-9). Most of that is portable; its Windows API plumbing is not.
* Four findings that change our plans: (1) Rufus has **no** known-good ISO hash check, **no** wimgapi fallback, **no** read-back verification and **no** headless mode (§0); (2) it **removed** the storage Windows-11 bypass as a no-op, so our five-bypass claim needs an on-device test (§4a); (3) its UEFI revocation pipeline (DBX/SBAT/SVN) is pure data plus a 60-line PE hash, which I verified against `osslsigncode` (§5); (4) our vendored `uefi-ntfs.img` is byte-identical to Rufus's current one and the signed loaders in it are not in Rufus's own DBX (§0, §5).
* Biggest gaps: an in-process ISO9660/UDF reader and a typed pre-flight `ImageReport` (§11-1), bootloader revocation report (§11-2), source-on-target / multi-partition / process-holding-the-device guards (§11-3), a fake-capacity test (§11-4), tail wipe (§11-5). Ten adoptions in §11, five things not to copy in §12.

### Runtime-downloaded boot assets (how Rufus keeps GRUB/Syslinux current)

All in `BootCheckThread` (`rufus.c:1491-2040`), and only when the target includes BIOS and the image is **not** being DD-written.
Server base is `https://rufus.ie/files` (`rufus.h:125,128`); every file is fetched with a sibling `.sig` and verified by
`ValidateOpensslSignature` (RSA-2048/SHA-256, public modulus compiled in, `pki.c:825-902`) in `DownloadSignedFile` (`net.c:356-426`).
Downloads go to `%LocalAppData%\Rufus\<component>-<version>\…` (`rufus.c:3478`, `FILES_DIR`) and are reused if present. After download the file's SHA-256 is looked up in
`sha256db` and logged ✓/✗ (`rufus.c` "IsBufferInDB", `iso.c` "IsFileInDB").

* **GRUB `core.img`**: ISO's version is read from `normal.mod` (`"GRUB  version %s"` / `"GRUB version %s"` — Fedora fixed the double space, `iso.c:1083-1172`). Suffixes are appended to name nonstandard builds: `-nonstandard` when the prefix dir is not `/boot/grub`, `-gdie` when the module references `grub_debug_is_enabled` (Ubuntu patches), and for the bare `2.06` the sanitised ISO label too (`iso.c:1150-1171`). The client then tries the full string and strips `.`/`-` components until the server has a match (`rufus.c:1821`). Falls back to the embedded 2.14.
* **Syslinux `ldlinux.sys` + `.bss`** for the ISO's exact version (`rufus.c:1884-1950`), `ldlinux.c32` for the v6 boot type (`rufus.c:1953-1976`), and replacement `menu.c32`/`vesamenu.c32` when the ISO's are smaller than 53,500 / 148,000 bytes (`rufus.h` `OLD_C32_THRESHOLD`; `rufus.c:1847-1880`).
* **EFI GRUB filesystem capability**: `GetGrubFs` greps the EFI GRUB binary for `fshelp` module names (`iso.c:1174-1189`); if it lacks FAT (or exFAT/NTFS when a >4 GB file exists) the image is forced to DD mode (`rufus.c:1424-1430`).
* Weakness worth not copying: `sbat_level.txt`, `sb_active.txt`, `sb_revoked.txt` and `Fido.ver` are fetched **without** a `.sig` (`stdlg.c:1717-1760`) — an attacker who can MITM TLS can only *weaken* the warnings, but still.

## 2. Device enumeration and safety (`src/dev.c`, `src/drive.c`, `src/smart.c`, `src/process.c`)

**Identity.** A target is `\\.\PhysicalDrive<N>`; `N` is the disk number from `IOCTL_VOLUME_GET_VOLUME_DISK_EXTENTS`, falling back to
`IOCTL_STORAGE_GET_DEVICE_NUMBER` (`drive.c:1062-1095`); a volume spanning two disks is dropped as RAID (`drive.c:1080`).
Internally the index is `N + 0x80` and every accessor goes through `CheckDriveIndex`, whose stated reason is that passing 0 would
open `C:` and zero its MBR (`rufus.h:70`, `drive.c:121-135`). No serial number is used for identity: Rufus remembers the
SetupAPI **device instance id** (for disable/enable), the parent **hub path + port** (for port cycling, `dev.c:1163-1171`), friendly name, label and size.
It re-selects "the same drive" after a refresh by index (`ChangeLog.txt` 2.18). Sirius's by-id serial path is stricter; keep it.
Display string `%s (Disk %d) [%s]` / `Label (E:) [size]` / `Multiple Partitions` (`MSG_046/047`); list sorted by size (`dev.c:1186-1200`).

**Which enumerators are trusted** (`dev.c:577-612`): `USBSTOR`; proprietary card-reader drivers `RTSUER CMIUCR EUCR`; UASP drivers
`UASPSTOR VUSBSTOR ETRONSTOR ASUSSTPT` (UASP disks hang off `SCSI`, so the list is split at `UASPSTOR`); generic `SCSI`; non-USB card readers
`SD PCISTOR RTSOR JMCR JMCF RIMMPTSK … GLREADER`. `STORAGE` is deliberately excluded: "used by Storage Spaces => DANGEROUS" (`dev.c:592`).
Card-reader disks under SCSI are recognised by hardware-id substrings `_SD_ _SDHC_ _SDXC_ _MMC_ _MS_ _MSPro_ _xDPicture_ _O2Media_` and the `&` variant (`dev.c:812-829`).
USB speed/VID:PID come from the hub (`IOCTL_USB_GET_NODE_CONNECTION_INFORMATION_EX`, V2, SuperSpeedPlus lane maths, BOS descriptor; `dev.c:115-260`),
and Rufus tells the user when a device runs below its capability (`dev.c:991`: "NOTE: This a USB 3.0 device operating at USB 2.1 speed").

**Elimination chain** (all in `GetDevices`, `dev.c:575-1230`), in order:
1. Not a disk interface, or no media (`dev.c:1040`), or `< MIN_DRIVE_SIZE` = 8 MB (`rufus.h:72`, `dev.c:1049`).
2. Non-USB **removable** (eSATA, internal removable bays): dropped unless Ctrl-Alt-F (`dev.c:950`). Non-USB with no VID:PID: "most likely a system drive => eliminate" (`dev.c:957-961`).
3. SCSI, non-UASP, non-VHD: must report removable, and *every mounted volume* must be `DRIVE_REMOVABLE` (`dev.c:1058-1073`).
4. **HDD heuristic** `IsHDD(...) > 0` → hidden unless "List USB Hard Drives" (`dev.c:1079`).
5. Cards larger than `MAX_DEFAULT_LIST_CARD_SIZE` = 500 GB (`rufus.h:89`, `dev.c:1086`).
6. Microsoft Dev Drives (`FSCTL_QUERY_PERSISTENT_VOLUME_STATE`, `drive.c:2667`), Windows Sandbox `PortableBaseLayer` VHD (`dev.c:1101`), Bitdefender ≤ 32 MB VHDs (`dev.c:1107`), VHDs when Alt-G (`dev.c:1111`).
7. **User ignore lists**: `IgnoreUsb01..08` as `0xVIDPID` (`dev.c:720,977`; documented in `res/rufus.ini:48-51`) and `IgnoreDisk01..08` as GPT disk-GUID strings (`drive.c:2698-2732`).
8. Rufus's own `UEFI:NTFS` helper volumes are hidden from the letters list (`dev.c:1121-1135`).
9. **The disk Rufus runs from and the system disk are removed** by comparing each drive letter with the app dir and `%SystemRoot%` (`dev.c:1139-1152`: "Removing %c: from the list: This is the … system disk").
Opening a device uses a **3 s timeout** (`CreateFileWithTimeout`, `dev.c:1030`, `stdio.c:570`) because some devices hang `CreateFile` forever.

**HDD-vs-flash score** (`smart.c:441-520`, tables `src/hdd_vs_ufd.h`, 312 lines). Positive = HDD. +3 if `DRIVE_FIXED`; size > 800 GB +15 (> 1800 GB another +15), < 128 GB −15;
model prefix table (`WDC ST# IBM MAXTOR … +10`, `SAMSUNG TOSHIBA +5`, `SANDISK KINGSTON LEXAR PNY … −15`); substring adjustments (`HDD SATA SCSI SSD +20`, `Flash Gadget SD-CARD −10`);
then VID and VID:PID tables. The header (`smart.c:~403-428`) says outright that it is a guess and disclaims it. Table data is derived from smartmontools `drivedb.h`, flashboot.ru and linux-usb.org (`hdd_vs_ufd.h:2-9`).
S.M.A.R.T. passthrough itself is compiled out (`#if defined(RUFUS_TEST)` / `#if 0`, `smart.c:42,361`). **Rufus's own safety story is "hide HDDs; show a big warning"**, and the cheat that lifts the hiding logs: "By using this unofficial cheat mode you forfeit ANY RIGHT to complain if you lose valuable data!" (`rufus.c:4250`).

**Pre-destruction sequence** (`FormatThread`, `format.c:1445-1700`; helpers in `drive.c`):
1. Open + **lock** the physical drive: `GetHandle` (`drive.c:138-216`) retries open 150 × 100 ms (`DRIVE_ACCESS_TIMEOUT` 15 s / `…RETRIES` 150, `rufus.h:68-69`) on sharing violation; after 50 failed tries it drops to write-sharing and **names the process holding the drive** (`GetProcessSearch`, `drive.c:176`); sends `FSCTL_ALLOW_EXTENDED_DASD_IO` (I/O boundary checks off), then `FSCTL_LOCK_VOLUME` in a loop for up to 15 s. If the lock fails it proceeds only when every holder had read-only access (`drive.c:200-214`).
2. **Unassign all drive letters** (`RemoveDriveLetters`, `drive.c:1231`) — and refuse if the *image* lives on this drive (`drive.c:1253` "Cannot use an image that is located on the target drive!"; also checked up front, `rufus.c:1524`, `drive.c:1214`).
3. Close the lock and let **VDS delete the partitions** (`format.c:1534`); on failure fall back to locking the logical volume (`need_logical`, `format.c:1540`) and turn physical locking off.
4. Reopen read-write; `RefreshDriveLayout` = `IOCTL_DISK_UPDATE_PROPERTIES` (`drive.c:2614`).
5. `FSCTL_DISMOUNT_VOLUME` (`drive.c:2110`).
6. **`ClearMBRGPT`: zero 8 MiB at the start and 1 MiB at the end** (`MAX_SECTORS_TO_CLEAR = 8 MB/512`, end = `/8`; `format.c:718-758`, `rufus.h:90`). The end part is best-effort ("Windows seems to be an ass about keeping a lock on a backup GPT").
7. `InitializeDisk` = `IOCTL_DISK_CREATE_DISK` RAW + update-properties (`drive.c:2626`); the comment at `format.c:1578-1583` says this alone is *not enough* (issue 759).
8. If steps 6-7 fail and VDS exists: **cycle the device** (SetupAPI disable/enable, `dev.c:315`) and retry once (`format.c:1593-1620`).
9. After partitioning, **zero the first ≤ 8 MiB of every new partition** because "we haven't found a way to reset Windows's cached view of a drive partitioning short of cycling the USB port" (`drive.c:2275-2280,2465`). Then VDS rescan, wait ≤ 15 s for the logical volume (`WaitForLogical`, `drive.c:997`).
10. On `ERROR_NOT_READY` after a failure, Rufus cycles the **USB port** (`IOCTL_USB_HUB_CYCLE_PORT`, `dev.c:263`, `rufus.c:3246-3251`; ≥ 10 s between resets).
11. On failure it lists blocking processes (`rufus.c:3215`) and probes whether Windows **Controlled Folder Access** is on (PowerShell, `rufus.c:3218-3240`).

Sirius equivalents that matter on Linux/macOS: step 6 (wipe the tail too: backup GPT, md-raid 1.0 superblocks and ZFS labels live there), step 9, step 2's "image is on the target" refusal, and 11 (name the process holding the device).

## 3. Image analysis (`src/iso.c`, `src/vhd.c`, `src/wue.c`, `src/rufus.c`)

**Design worth copying: one walker, two modes.** `ExtractISO(src, dest, scan)` (`iso.c:1222`) is used for both the read-only *scan* pass
and the later *extract* pass; `check_iso_props` (`iso.c:249`) runs in both, with `scan_only` selecting the scan-time rules. Detection
and extraction therefore cannot disagree about what is on the image — the same discipline as our invariant 3. It opens **UDF first,
then ISO9660** (`iso.c:1287`, again in `ExtractISOFile` ~1634), which is the same lesson as our invariant 4, learned the hard way by Rufus
(Joliet is disabled for the scan if Rock Ridge is on, `iso.c:1306-1315`). Everything runs through a vendored libcdio (`src/libcdio/{iso9660,udf}`),
in-process, no mount, no external tool.

**What the scan records** (`RUFUS_IMG_REPORT`, `rufus.h:437-481`):

| Field(s) | Rule (all case-insensitive) | Cite |

(`format.c:1941-1994`: `ExtractISO`, then per-case fix-ups: KolibriOS loader copy, Win7 `bootmgfw.efi` pulled out of `install.wim` into `\efi\boot\bootx64.efi` when the ISO has `bootmgr.efi` but no `boot*.efi` (`format.c:1976-1994`, `HAS_WIN7_EFI` `rufus.h:381`), WinPE patching, unattend injection).

### 4b. Windows To Go (`wue.c:853-1115`, `format.c:1470-1500,1944-1960`)
Offered when `HAS_WINTOGO` = bootmgr ∧ EFI-bootable ∧ has `install.*` (`rufus.h:392`), host ≥ Windows 8, NTFS only (`MSG_097`). Layout: ESP **260 MB first** (on hosts ≥ 1703 that can mount two partitions of a removable drive) + **MSR 128 MB** + NTFS (`drive.c:2321,2370-2395`, "every GPT disk we RUN Windows from must have an MSR"). Index chosen by a picker; default is the host's own edition (`wue.c:913-921`). Steps: `wimlib` apply to the volume (`WimApplyImage`), format the ESP with the **Large-FAT32 code** because VDS cannot format removable ESPs (`wue.c:1030-1050`), run the **host's** `bcdboot.exe <vol>\Windows /v [/offline] [/bootex] /f UEFI|BIOS|ALL /s <esp>` (`wue.c:1053-1085`), then `bcdedit /store …\BCD /set {default} recoveryenabled no` (`wue.c:1095`). Warnings: non-FIXED drive ⇒ "Windows will most likely freeze during boot" (`MSG_098`); 1809 ISOs ⇒ the `WppRecorder.sys` BSOD notice, with the reason Rufus cannot fix it: "a Microsoft copyrighted file, so we cannot legally embed a copy" (`MSG_133`, `wue.c:961`). **No BCD store is written by Rufus itself — it needs Windows's `bcdboot`** — so this is Windows-host-only unless we ship our own BCD generator (large).

### 4c. Persistence (`format.c:1773-1790`, `format_ext.c`, `iso.c:482-545`, `ui.c:682-779`)
Only for ISO mode, `HAS_PERSISTENCE` = (Syslinux ∨ GRUB) ∧ ¬(Windows ∨ ReactOS ∨ KolibriOS) (`rufus.h:393`); it **disables the ISOHybrid DD option** (`rufus.c:1555`). Slider max = `DiskSize − 110 % × projected_size` (`PROJECTED_SIZE_RATIO`, `ui.c:728-733`), min 256 MiB (`MIN_EXT_SIZE`, `rufus.h:74`). Partition type MBR `0x83` / GPT Linux-data (`drive.c:2505,2523`), placed after the main partition and before the UEFI:NTFS helper (`drive.c:2398-2415`), formatted **first** "to avoid concurrent access" by Windows (`format.c:1773`). Label `casper-rw` (Ubuntu, if the ISO has `/casper`) or `persistence` plus a `persistence.conf` containing `/ union\n` (**the trailing LF is mandatory**, `format_ext.c:451`) for Debian-likes. Kernel line edits: add `persistent` after `file=/cdrom/preseed` (Ubuntu), or `boot=casper`→`boot=casper persistent` (Mint), or `/casper/vmlinuz` → `… persistent` (Ubuntu 23.04/24.04 GRUB), or `boot=live` → `boot=live persistence` (Debian); remove Ubuntu's `maybe-ubiquity` (`iso.c:487-545`). Ubuntu images before 2019-08-01 cannot work because of Ubuntu bug 1489855 (`ChangeLog.txt:339-346`). ext2/ext3 only: ext4 is silently downgraded to ext3 (`format_ext.c:276`); ≥ 2^32 blocks refused (`format_ext.c:313`).

### 4d. Bad blocks and fake-capacity detection (`src/badblocks.c`, `format.c:1620-1690`)
Derived from e2fsprogs `badblocks -w` (header: GPL). Destructive read-write only. Block = 512 KiB, 64 blocks per I/O (`BB_BLOCKS_AT_ONCE`), abort after **256** bad blocks (`badblocks.h:36-38`). Pattern sets (`rufus.h:103-111`, UI "Number of passes"): 1 pass `{0x55}`; 2 passes `{0x55,0xAA}`; SLC 4 passes `{0x00,0xFF,0x55,0xAA}`; MLC `{0x00,0xFF,0x33,0xCC}`; TLC `{0x00,0xFF,0x1C71C7,0xE38E38}` (24-bit repeating patterns made of alternating 3-bit runs, aimed at 3-bit cells); 0x55/0xAA replaced 0x00/0xFF in the cheap pass in 3.13 (`ChangeLog.txt:278`). **Fake-capacity detection**: on the first pass a 64-bit **block number is written at a random byte offset inside every block**, and the read-back compares against the same sequence (`badblocks.c:452-455,479-485,527-533`) — so a stick that wraps writes modulo its real size fails, which a constant pattern would not. Results: read/write/corruption counts (`MSG_011`), a log `rufus_YYYYMMDD_HHMMSS.log` in the user profile (deleted if clean), and when bad blocks are found an **Abort / Retry / Ignore** box (`MSG_010/012`, `format.c:1662`); afterwards `ClearMBRGPT` again ("else all kind of bad things happen"). Alt-B disables the id-stamp (`rufus.c:4001`). It runs *after* the confirmation, before partitioning, so it costs hours on a big stick; there is no sampled "quick" mode. Our `--full-format` is read-only and PROJECT-STATE already says it is not a counterfeit test; this is the thing that would be.

### 4e. Quick vs full, autorun, "old BIOS fixes", MBR options
* **Quick** (`IDC_QUICK_FORMAT`) maps to `FormatEx`'s quick flag (`format.c:628-631`); unchecking = Windows' own slow format (tooltip `MSG_162`). Large FAT32 and ext2/3 ignore it for data (only metadata + journal laziness, `format_ext.c:436-439`), so "full" is meaningful only for the Windows-formatted types.
* **Create extended label and icon files** (`MSG_166`): writes `autorun.inf` with `label=` and `icon=autorun.ico` (UTF-16LE, `icon.c:161-195`) — carries labels > 11 chars or non-ASCII on FAT and a device icon; keeps an existing `autorun.inf`; AV products that block it are called out (`stupid_antivirus`, `iso.c:126`). Explorer-only; ignore for us.
* **"Add fixes for old BIOSes (extra partition, align, etc.)"** (`MSG_169`): first partition aligned to a track-multiple (2 × `CEILING_ALIGN(bytes_per_track, cluster)`) instead of 1 MiB (`drive.c:2357-2360`) **and** an extra one-track partition of type `0xEA` at the end (`drive.c:2418-2421,2508`); partitions of that type are ignored later when counting (`drive.c:2025`).
* **Use Rufus MBR / BIOS ID**: `use_rufus_mbr` defaults to TRUE, Alt-A toggles (`rufus.c:133`); 0x81 masquerade only for XP-era WinPE (`format.c:763,879`). `FormatEx` clobbers the LBA flag, so the type byte is rewritten after format: FAT16 → `0x0E`, FAT32 → `0x0C` (`format.c:796-812`).
* **MBR type bytes written** (`drive.c:2470-2510`): FAT16 `0x0E`, FAT32 `0x0C`, NTFS/exFAT/UDF/ReFS `0x07`, ext `0x83`, UEFI:NTFS helper and ESP `0xEF` ("as an MBR ESP somehow seems to be okay"), BIOS-compat partition `0xEA`. GPT types: Microsoft basic data, ESP, MS-reserved, Linux data; the UEFI:NTFS helper is basic data **with GPT attribute "no drive letter"**, deliberately *not* an ESP because "the Microsoft Windows installer errors out at 'Copying Windows Files' because it just can't handle 2 ESPs" (`drive.c:2512-2520`). Sirius already does both *(code)* `lib.rs:665-701`. Alt-P flips a GPT ESP to basic data and back for Windows 10+ (`drive.c:1579`, `rufus.c:4118`).

### 4f. The scheme × target matrix (`rufus.c:258-372`, `SetAllowedFileSystems` `rufus.c:171-227`)

| Boot selection | Partition scheme offered | Target offered |
|---|---|---|
| Non bootable | MBR, GPT, **SFD** ("super floppy", no partition table) | "BIOS or UEFI" only |
| Image, **not** EFI-bootable | MBR | "BIOS (or UEFI-CSM)" |
| Image, EFI-only | MBR, GPT | "UEFI (non CSM)" (MBR ⇒ disk signature `0x49464555` = "UEFI", helper type `0xEF`, `drive.c:2561`, `rufus.h:94`) |
| Image, BIOS+EFI, non-Windows (or Alt-E, or WTG) | MBR, GPT | MBR ⇒ "BIOS or UEFI"; GPT ⇒ "UEFI (non CSM)" |
| Image, BIOS+EFI, Windows (default) | MBR, GPT | MBR ⇒ "BIOS (or UEFI-CSM)" (UEFI hidden); GPT ⇒ "UEFI (non CSM)". Default scheme **GPT** if the image has EFI (MBR with Alt-E). |
| MS-DOS, FreeDOS, Syslinux, ReactOS, Grub2, Grub4DOS | MBR only | BIOS |
| UEFI:NTFS standalone | MBR, GPT (GPT default) | UEFI |
| any, disk > 2 TB | GPT pre-selected (`rufus.c:325`); choosing MBR gives `MSG_134` "…will leave %s of disk space unavailable. Are you sure you want to continue?" | |
| Syslinux < 5 and a > 4 GB file, no Windows/PE/GRUB | MBR removed (Syslinux 4 cannot do NTFS) | |

Filesystem gating per boot type (`rufus.c:171-227`): NTFS always unless GRUB-EFI without NTFS driver; FAT16/32 only if `IS_FAT32_COMPAT` (no > 4 GB file, or the splittable-WIM case with Alt-E, `rufus.h:386`); ext2/3/4 only for the Grub2 boot type; exFAT/NTFS for UEFI:NTFS. Cluster tables and the `FAT32_CLUSTER_THRESHOLD = 1.011` fudge (sizes change slightly *above* a power of two) are `rufus.c:449-640`, already reimplemented in `format.rs`.
**UEFI:NTFS helper placement**: size = embedded image (1 MiB) rounded up to a track, placed from the **end** of the disk backwards (`last_offset − size`, track-aligned; GPT keeps 33 sectors for the backup table, `drive.c:2428-2437`). It is added when the image is EFI-bootable and fs ∈ {NTFS, exFAT} — **except** a Windows ISO on MBR/BIOS without Alt-E (`format.c:1478-1490`).

## 5. Hashing and verification (`src/hash.c`, `src/pki.c`, `src/db.h`)

**What Rufus hashes.** MD5, SHA-1, SHA-256, optional SHA-512 (Alt-H, `hash.c:107`, `rufus.c:4056`) of the *selected image*, in **one read pass fanned out to one thread per algorithm** over two 2-deep buffers (`HashThread` `hash.c:2004-2135`, `IndividualHashThread` `hash.c:1966`), with SHA-1/SHA-256 x86 SHA-NI paths (`hash.c:126,162,429,730`). Result: log lines plus a dialog with the digests (`hash.c:1888`). **Nothing is compared to anything** — the user must paste into a checksum site themselves; the truncated-ISO notice itself tells you to "verify that the MD5 or SHA checksums match the official ones. Note that you can compute the MD5 or SHA in Rufus by clicking the (✓) button" (`MSG_298`). Other digest uses: `sha256db` (own downloads, ✓/✗), pinned SHA-256 of `oscdimg.exe`/`diskcopy.dll` before running (`rufus.h:133-147`, `iso.c:2238-2243`), MD5 of every file Rufus modified to patch `md5sum.txt` (§3), PE256 (below).

**Post-write verification: none.** `WriteDrive` (`format.c:1151`) writes and returns; the only other thing that touches the device afterwards is `RefreshDriveLayout` and a remount attempt (`format.c:2043-2068`). For extracted ISOs the only follow-up is `chkdsk` on NTFS (`CheckDisk`, `format.c:686,2022`) and, if the user ticked "runtime UEFI media validation", the **boot-time MD5 loader** (§1 `md5/`) that re-hashes every file from the firmware. So our read-back verification is a genuine edge over Rufus and `dd`; the md5sum loader is the only comparable thing Rufus has, and it detects *later* corruption too. (README also says Etcher does not read back; my recollection is that Etcher has a post-write "Validating…" phase, so re-check that sentence before it stays in the README — I could not verify it from here.)

**PE256 / Authenticode hash** (`PE256Buffer` `hash.c:1835`, `efi_image_parse` `hash.c:1686`, derived from U-Boot's `efi_image_loader.c`, GPL-2+): SHA-256 over the PE with three holes — the 4-byte `CheckSum` field, the 8-byte Certificate-Table data-directory entry, and the certificate blob itself — then each section's raw data in file-offset order, then any trailing bytes before the certificate; buffer must be 1 KB-64 MB. The code comment warns that Windows' `ImageGetDigestStream` cannot be used because it includes the checksum field. **I re-implemented it in Python and it matches `osslsigncode`'s "Calculated message digest" byte for byte on `uefi-ntfs.img:EFI/Boot/bootx64.efi` (`ed319fe0…0d0b`)**, so the algorithm above is right.

**Revocation pipeline** (`GetBootladerInfo` `rufus.c:1252` → `IsBootloaderRevoked` `hash.c:2399`): for each `efi_boot_entry` collected by the scan, the loader is read straight out of the ISO into memory (`ReadISOFileToBuffer` `iso.c:1719`); signer comes from the PKCS#7 blob (`GetIssuerCertificateInfo` `pki.c:400`); **unsigned loaders are skipped**. Then, in order, first hit wins:

| # | Test | Data | Result bit |
|---|---|---|---|
| 1 | PE256 hash ∈ UEFI **DBX** | `res/dbx/*.efiauth2`, newer one from GitHub if available (`hash.c:2229`) | `2` |
| 2 | PE256 ∈ **SkuSiPolicy** revoked list | `pe256ssp[]` — **empty in this tree** (§1) | `4` (the only value that selects the "Windows Recovery Screen … 0xc0000428" wording, `rufus.c:1538-1543`) |
| 3 | **Linux SBAT**: `.sbat` section lines `product,generation,…` vs minimum levels | `sbat_level.txt` (`sbat,1,2025051000 / shim,4 / grub,5 / grub.proxmox,2`) | `8` |
| 4 | **Windows SVN**: a PE resource named like an all-caps product in the same file (`BOOTMGRSECURITYVERSIONNUMBER,0x70000`) holds a `uint32` `major<<16|minor` that must be ≥ the minimum | same file, `hash.c:2289` | `16` (generic "Security Violation" wording) |
| 5 | issuer **certificate thumbprint** (SHA-1) ∈ revoked list — *expert mode only* (`hash.c:2341`) | `sb_revoked.txt` (currently only `Microsoft Windows Production PCA 2011`, `db.h:148`) | `32` |

`has_secureboot_bootloader` bit 0 records "signed by a Secure Boot authority" (one of the four thumbprints in `db.h:134-142`: PCA 2011, UEFI CA 2011, Windows UEFI CA 2023, Microsoft UEFI CA 2023). On a hit the user gets an OK/Cancel box: "Rufus detected that the ISO you have selected contains a UEFI bootloader that has been revoked and that will produce %s, when Secure Boot is enabled on a fully up to date UEFI system. – If you obtained this ISO image from a non reputable source, you should consider the possibility that it might contain UEFI malware and avoid booting from it. – If you obtained it from a trusted source, you should try to locate a more up to date version, that will not produce this warning." (`MSG_339`; `%s` = `MSG_340` "a "Security Violation" screen" or `MSG_341` "a Windows Recovery Screen (BSOD) with '%s'"). If **not** revoked it prints the Secure Boot "gotchas" in the log, e.g. "This bootloader will fail Secure Boot validation on systems that have not been updated to the latest Secure Boot certificates" for CA-2023-signed loaders and "…may fail … *some* systems, unless you enable 'Microsoft 3rd-party UEFI CA' in your 'BIOS'" for the UEFI CA 2011 (`hash.c:2440-2455`) — the same caveat our `WindowsLayout::caveat()` carries for UEFI:NTFS.
**Check I ran:** with my parser, `bootx64/ia32/aa64.efi` from `uefi-ntfs.img` and `res/md5/boot{x64,ia32}.efi` are signed and **not in Rufus's own shipped DBX** (x64 ≈ 291 unique SHA-256 entries, ia32 47, aarch64 22, arm 16). Anything we vendor should get this test in CI.

## 6. Download integration and self-update (`src/net.c`, `src/pki.c`, `src/stdlg.c`)

**"Download ISO" = run Fido.** The Select button becomes a split button only if a background check (`CheckForFidoThread` `stdlg.c:1698`) can fetch `https://rufus.ie/Fido.ver`, finds the `z1` token whose URL **must start with `https://github.com/pbatard/Fido`** (`stdlg.c:1757`), and `IsDownloadable` says it exists (`net.c:999`); the same thread refreshes `sbat_level.txt`, `sb_active.txt`, `sb_revoked.txt`. `DownloadISOThread` (`net.c:794-985`): download the LZMA-compressed script + `.sig`; RSA-verify (`net.c:836`); decompress with bled to < 1 MB; write it to `%TEMP%\<GUID>.ps1` created **restricted and read-only** (`CreateFileRestrictedU`, `net.c:881`; this is the CVE-2026-2398/23988 fix, `ChangeLog.txt:42`); **Authenticode-validate the local `.ps1`** (`ValidateSignature(INVALID_HANDLE_VALUE, …)`, `net.c:918`) because PowerShell's own policy cannot express "signed by a cert I trust"; run `powershell.exe -NonInteractive -Sta -NoProfile -ExecutionPolicy Bypass -File … -PipeName <guid> -LocData "<18 pipe-separated localised strings>" -Icon … -AppTitle … -PlatformArch …` (`net.c:912`); Fido shows its own UI (version → release → edition → language → architecture), then writes the final `https://…` URL to the inbound **named pipe** (`net.c:925-940`). Rufus then asks for a save path and streams the file itself with progress/ETA (`DownloadToFileOrBuffer`, `net.c:947-975`) and auto-scans the result. **There is no checksum verification of the ISO** (the API does not provide one). Failure UX: `MSG_144` "Download of Windows ISOs is unavailable due to Microsoft having altered their website to prevent it." with a "Download using a browser" button (`MSG_143`), and a PowerShell 3.0 requirement prompt (`MSG_145/146`). The same pipeline also serves UEFI Shell ISOs (README). The Fido script itself is *not in this repository*.

**Signed content from rufus.ie.** Every asset is `file` + `file.sig` (256-byte RSA-2048/SHA-256 PKCS#1, public modulus compiled in; a Windows CryptoAPI bridge that byte-reverses modulus and signature, `pki.c:825-902`; added in 3.2, `ChangeLog.txt:401`). Not covered by it: the three small revocation text files and `Fido.ver` (HTTPS only).

**Self-update** (`CheckForUpdatesThread` `net.c:535-775`): opt-in prompt on first run ("Do you want to allow Rufus to check for application updates online?" `MSG_004/005`) plus a disclosure of exactly what the server sees — OS architecture and version, app version, IP; "we may keep the information … for at most a year … will not willingly disclose" (`MSG_180-184`) and "Rufus does not install or run background services, therefore update checks are performed only when the main application is running" (`MSG_186`). Interval Disabled/Daily/Weekly/Monthly/Custom (`MSG_013-017`; default 24 h `net.c:50`). The version file name is tried from most to least specific by stripping trailing components — `rufus_win_x64_6.2.ver` → `rufus_win_x64_6.ver` → … (`net.c:635-669`) — which lets the server sunset OS versions or give an arch its own download; channels `release`/`beta`/`test` (`net.c:541`). The `.ver` is a ≤ 64 KB text file (`version`, `platform_min`, `download_url[_arch]`, `release_notes`) parsed after **whitelisting characters** (`parser.c:913-962`) and RSA-verified (`net.c:717`). **The server's `Date:` header is the only clock trusted** for "when did I last check" (`net.c:684-697`), with a log line when the local clock is > 10 min off. The downloaded installer is accepted only if (`pki.c:728-815`): the Authenticode **common name is one of three pinned strings** (`Akeo Consulting`, `Akeo Systems`, `Pete Batard`, `pki.c:46`) **and** the cert country is `IE` (`pki.c:48`); `WinVerifyTrust` with whole-chain revocation and Mark-of-the-Web; and a **rollback guard** — the new file's RFC-3161 timestamp must not be older than the running binary's, with nested timestamps required to agree within ~1 minute (`pki.c:700-707,799`). It then relaunches itself with `-w 150` to wait for the old process's global mutex (`stdlg.c:1927`; usage text `rufus.c:3277`). DBX updates piggy-back on the same timer (`net.c:576-580`).
Release engineering: Authenticode with timestamp (`_sign.cmd`), dual SHA-1/SHA-256 until 2.7, ALPHA builds signed from a CI-secret PFX, a **VirusTotal upload + monitor** step on every push (`vs2026.yml` "Upload to VirusTotal") — needed because release binaries are **UPX/LZMA-packed** (`vs2026.yml:116`, `mingw.yml:87`) which AVs dislike — x64/x86/arm64 matrix, CodeQL and Coverity workflows, a dedicated `setup.yml` that prints SHA-256 of the embedded wrapper.

## 7. Formatting and the write loop (`format.c`, `format_fat32.c`, `format_ext.c`, `stdio.c`)

**Dispatcher** `FormatPartition` (`format.c:665`): FAT32 on a disk > `LARGE_FAT32_SIZE` (32 GiB, `rufus.h:112`) or Alt-L or an ISO→ESP write ⇒ own formatter; ext2/3 ⇒ own formatter; VDS if Alt-V; else `fmifs.dll!FormatEx` with a callback and **4 retries 5 s apart** (`format.c:584-663`). FAT32 is not offered at ≥ 2 TB (`MAX_FAT32_SIZE`, `rufus.c:509`).

**Large FAT32** (`format_fat32.c:152-480`, Tom Thornhill/Ridgecrop's `fat32format`, extended): validated against hard limits first — < 65 536 sectors refused (`:246`), ≥ 2^32 sectors "max 2TB" (`:252`), **< 65 536 clusters refused "will be misdetected as FAT16"** (`:388`; note Rufus's floor is 65 536, ours is the spec's 65 525 — Rufus has a margin), > 2^28 clusters refused (`:382`). Layout: 2 FATs, FSInfo at sector 1, **backup boot sector at 6** (+ backup FSInfo at 7), media `0xF8`, `DrvNum 0x80`, OEM `MSWIN4.1`, jump `EB 58 90` ("jmp.s $+0x5a is 0xeb 0x58, not 0xeb 0x5a. Thanks Marco!"), volume id from the clock, the `55 AA` signature **also at the end of the sector when the sector isn't 512 bytes** (FATGEN103 note, `:336-342`), label written afterwards with `SetVolumeLabel` (`:466-474`) while the boot sector says `NO NAME`. FAT size uses the corrected formula from the syslinux list: `FatSz = ⌊(Total − Reserved + 2×SecPerClus) / (SecPerClus×BytesPerSec/4 + NumFATs)⌋ + 1` (`:134-146`); reserved sectors start at 32 and are **grown so that reserved + FATs ends on a 1 MiB boundary** so the data region is aligned (`:313-320`, 4.4). Default cluster when the caller passes 0: < 64 MB 512 B, < 128 MB 1 K, < 256 MB 2 K, < 8 GB 4 K, < 16 GB 8 K, < 32 GB 16 K, < 2 TB 32 K, else 64 K (`:262-278`); the GUI normally passes the table from `rufus.c:449-640` instead. Only the reserved area, both FATs and the root cluster are zeroed, in 128-sector bursts (`:420-435`) — "full format" does not exist for it. It writes the PBR itself, from inside the lock (`:452-460`), because "have issues when trying to write the PBR after a remount".

**ext2/ext3** (`format_ext.c:220-500`, on top of 77 vendored e2fsprogs files in `src/ext2fs/` and an NT I/O manager): `mke2fs.conf`-derived table (floppy/small/default/big/huge ⇒ block 1 K/1 K/4 K/4 K/4 K, inode ratio and size, `:224-230`), 5 % reserved, features `dir_index filetype large_file sparse_super xattr` (+`journal` for ext3), default mount opts `xattr user + acl`, creator OS = Windows, journal size halved and `LAZYINIT` when Quick (`:436-439`) because journal init "is really killing us", `ext4` ⇒ ext3 with a log line, ≥ 2^32 blocks refused. Mounted by assigning a letter via the Windows `AltMountVolume` path because Windows will not do it. Minimum 256 MiB.

**NTFS compression**: Alt-N sets `FP_COMPRESSION`; after `FormatEx` it calls `EnableVolumeCompression(FPF_COMPRESSED)` (`format.c:640-655`). Boot files must then be re-uncompressed: `compact /u bootmgr* efi/boot/*.efi` (`iso.c:1588`; issue 1381).

**Label sanitisation** (`ToValidLabel` `format.c:263-330`, called for everything below ext at `format.c:1797`): FAT16/FAT32/exFAT — drop `* ? , ; : / \ | + = < > [ ] "`; tab and `.` → `_`; **any code point ≥ 0x80 → `_`** ("A FAT label that contains extended chars will be rejected"); **uppercase**; truncate to 11; **if more than half the characters are `_` replace the whole label by the size ("7_9 GB")**. NTFS/UDF/ReFS — only tab and `.` → `_`, case kept, truncate to 32. The sanitised value is stored back (`img_report.usb_label`) and later re-read from the mounted volume because "Windows may have altered it from the name we proposed, and we require an exact label, to patch config files" (`format.c:1870-1878`). The unicode label can still reach Explorer through `autorun.inf` (§4e). The default proposed label is the **ISO's** label, else the previous label, else a size string (`rufus.c:690-720`).

**Raw/DD write loop** (`WriteDrive` `format.c:1151-1443`):
* Buffer `DD_BUFFER_SIZE` = **32 MiB**, rounded to the sector size and **allocated sector-aligned** (`_mm_malloc(buf_size × 2, SectorSize)`, `:1339-1346`), because raw-device I/O fails on unaligned/odd sizes; the last read is rounded up to a sector multiple (`:1373`).
* **Double buffering** (`NUM_BUFFERS` = 2, `format.c:62`): an overlapped read of buffer N+1 is started *before* the synchronous write of buffer N (`:1350,1389`). The read wait has a 15 s timeout (`DRIVE_ACCESS_TIMEOUT`). Reads are clamped to the image/virtual-disk size because mounted VHDs "start returning ERRONEOUS DATA for sectors before the end of the disk" if over-read (`:1389`).
* **Retries**: up to `WRITE_RETRIES` = **4** attempts per buffer; each failure logs `Write error at sector N: <Win32 text>` (or `Wrote X bytes, expected Y` for a short write), sleeps `WRITE_TIMEOUT` = **5 s**, seeks back to the buffer's start, sleeps another 200 ms, and retries; on the 4th, `ERROR_WRITE_FAULT` (`:1392-1417`). Cancellation is checked at the top of every attempt (4.15 improved it). **There is no special case for write-protected media or a pulled stick**: both are just failed `WriteFile`s and end up as the generic `MSG_065` "Write error." after ≈ 15 s of retries. (`ERROR_WRITE_PROTECT` has its own text, `MSG_054`, but only from the `FormatEx` callback, `format.c:155`.)
* Drives > 1 TB sometimes report **0 bytes written on success**; `WriteFileWithRetry` accepts that as "possible short write" when `large_drive` (`stdio.c:615-660`, `ChangeLog.txt:496`).
* Compressed images: bled decodes into a **sector-boundary re-blocker** `sector_write` (`format.c:1092-1149`) because "Some compressed images use streams that aren't multiple of the sector size"; a final partial sector is padded and written with the error only logged (`:1303-1313`).
* Compressed/VHD progress is in decompressed bytes using the container's declared size (`bled_get_uncompressed_size`, `vhd.c:100-104`).
* **Zero drive** (Alt-Z) and **fast-zero** (Ctrl-Alt-Z) use the same loop with a zero buffer; fast-zero first reads the block and **skips the write if it is already uniformly 0x00 or 0xFF** (erased flash), and after any real write skips reading for the next 15 blocks (a back-off, `throttle_fast_zeroing = 15`, `format.c:1190-1260`). 3.13 added zeroing progress to the log.
* Throttling: none on the device. UI updates are limited to one per `2×MAX_REFRESH` = 50 ms (`ui.c:1296`), the log gets up to 80 `+` markers per progress sequence (`uprint_progress` `stdio.c:146-157`, `MAX_MARKER`), and the taskbar button mirrors progress.
* Progress is **phase-weighted**: each of analyse / bad blocks / zero MBR / partition / format / create-fs / fix MBR / copy / patch / finalize / extract-zip gets a fixed number of "slots" or a share of the remainder if it is analog (`InitProgress` `ui.c:1172-1257`, `OP_*` `rufus.h`), so the single bar does not restart per phase. Rate/ETA come from GNU wget's `bar_update` — 150 ms samples, ≥ 3 s window, ring of 20, with ETA flicker suppression (`ui.c:1306-1410`); a bare Alt press cycles percent → rate → remaining time (`rufus.c:4264`).

* Style rules visible across the file: one ALL-CAPS phrase for the consequence, plain second paragraph for the remedy; titles are nouns ("Unsupported image"); where a choice exists, both choices are restated in the body; every dialog that can recur has a "Do not show this message again" (`MSG_127`, `NotificationEx` `stdlg.c:786`) and an optional "More information" button that opens a URL or a callback (`rufus.h` `notification_info`).

**Translation plumbing.** Every string is an id (`MSG_000…MSG_374`, `MSG_9xx` = store listing only) fetched with `lmprintf(MSG_id, …)` (`localization.c:363`); dialogs are retranslated by control id in `g IDD_…` groups. One 1.4 MB `rufus.loc` carries 38 languages (`# • v4.14 "en-US" …` header), a language may `b`ase on another so a dialect only overrides, translators get `#` hints and a `.po` round-trip (`res/loc/po`, `pollock/`). Windows LCIDs map to languages in the `l` line, RTL is an attribute, and the file can be replaced by an external one for testing. Alt-Y exists "for translators": it makes the update check always succeed so every update dialog can be seen (`rufus.c` Alt-Y).

**Log window.** Everything the program decides is `uprintf`'d: environment (dirs, Windows build, `bcdboot` capability, SHA-NI), drive properties (type, size, sector size, CHS, partition table with type names, FS signature sniff, disk id, `has_mbr_uefi_marker`), the ISO report (§3), each filesystem op, each retry. A button saves it; it is auto-saved on exit to `%LocalAppData%\Rufus\` (3.15) and optionally persisted (Ctrl-P, `SETTING_PERSISTENT_LOG`). USB enumeration detail is behind Alt-. (`uuprintf`). The README promises "extensive information about what it is doing, either through its easily accessible log, or through the Windows debug facility".

**Command line and portable mode.** Only `-x/--extra-devs`, `-g/--gui`, `-i/--iso=PATH`, `-l/--locale`, `-f/--filesystem`, `-w/--wait` (`rufus.c:3265-3285`) — a launcher, not a tool. A `rufus.ini` next to the exe — **even an empty one** — switches storage from the registry to that file (`res/rufus.ini:1-6`); the exe named with a `p` creates it on first run (`rufus.c:3555`). Hidden settings documented there and in `settings.h:30-60`: `ShowAdvancedDriveProperties`, `ShowAdvancedFormatOptions`, `EnableUsbDebug`, `DisableFakeDrivesCheck`, `EnableWindowsDualUefiBiosMode`, `ForceLargeFat32Formatting`, `EnableFileIndexing`, `PreserveTimestamps`, `UseProperSizeUnits` ("Disable the whole Kibi/Gibi nonsense"), `EnableVmdkDetection`, `IgnoreBootMarker`, `UseVds`, `IgnoreUsb01-08`, `IgnoreDisk01-08`, `DisableLGP` (suppress group-policy toggling that hides Windows's new-drive popups), update interval/beta channel/verbose. Each has a matching Alt-key "cheat mode" (list at `rufus.c:3985-4300`, e.g. Alt-F HDDs, Ctrl-Alt-F non-USB removable, Alt-B fake detection, Alt-E dual UEFI/BIOS Windows, Alt-I/J/K ISO/Joliet/Rock Ridge, Alt-L large FAT32, Alt-M ignore boot marker, Alt-N NTFS compression, Alt-O optical→ISO, Alt-P ESP↔basic data, Alt-S size check, Alt-T timestamps, Alt-U decimal units, Alt-V VDS, Alt-W VMDK, Alt-Z/Ctrl-Alt-Z zero drive, Ctrl-Alt-E expert mode, Ctrl-Alt-D dark mode, Alt +/- thread priority).

## 9. Everything else worth knowing

* **Privilege and Windows hygiene** (`stdfn.c`, `process.c`, `rufus.manifest`): manifest `requireAdministrator` (`rufus.manifest:29`), re-checked with `IsCurrentProcessElevated` (`stdfn.c:1038`) → `MSG_288/289` "This application can only run with elevated privileges" (`rufus.c:3789`); `SeBackup/SeRestore/TakeOwnership` for loading offline hives and fixing ACLs (`stdfn.c:1089-1180`); single-instance global mutex with `MSG_001/002` "Another Rufus application is running" (`rufus.c:3808`); a startup log of every directory; `NoDriveTypeAutorun` toggled for the run and restored on exit (`SetNDTA` `stdfn.c:956`, Alt-X deletes it if the app crashed) and a WinEvent hook that auto-dismisses Windows's own "You need to format the disk" popups (`SetAlertPromptHook` `stdlg.c:2332`).
* **`process.c`** is a trimmed copy of System Informer (Process Hacker): `NtQuerySystemInformation(SystemExtendedHandleInformation)`, per-handle access mask (0x01 read, 0x02 write, 0x04 exec), command lines of 32- and 64-bit processes, a 5 s watchdog thread (`SEARCH_PROCESS_TIMEOUT`), "ignore stale processes". Used before format (`rufus.c:3120-3130`), during lock retries (`drive.c:176,206`) and after failures (`rufus.c:3215`). The Linux/macOS equivalent is a `/proc/*/fd` + mountinfo scan (Linux) or `lsof +D`/`fuser` (macOS) and is cheap.
* **Hot-plug discipline**: device-change messages are ignored while scanning an ISO (it may mount one, `dont_process_dbt_devnodes` `rufus.c:79,1289`), a hot-plug during an operation is queued and replayed after (`queued_hotplug_event` `rufus.c:2291,3160`).
* **Security history in `ChangeLog.txt`** (a to-do list of attack classes to pre-empt): DLL side-loading ×3 (3.18, 4.7 CVE-2025-26624; fixed with delay-loading, see the comment at `pki.c:782`), TOCTOU in Fido execution (CVE-2026-2398/CVE-2026-23988), "replacement vulnerabilities for `diskcopy.dll` and `oscdimg.exe`" (4.12; now locked-then-hashed, `iso.c:2230-2243`), unrestricted XML entity expansion in the bundled `ezxml` (4.15), "multiple potential vulnerabilities" (4.5). Reporting policy: e-mail, 48 h response (`SECURITY.md`).
* **`libcdio`** is a stripped subset (`src/libcdio/{iso9660,udf,driver}`) used only as a file-image reader; two stubs make it link without a CD driver (`iso.c:73-74`). It gives Rufus, in-process and on a file: ISO9660 + Joliet + **Rock Ridge** (symlinks, `CE`, deep dirs `PL`), UDF 1.02+ with symlinks, multi-extent files, and El-Torito boot images exposed as virtual `/[BOOT]/<n>-<media>-….img` files in the 7-Zip style (`libcdio/iso9660/iso9660_fs.c:63-95,1508,1707`) — which is what the `efi.img` / `0-Boot-HardDisk.img` handling in §3 relies on. That reader is the single biggest enabler of Rufus's portability to "no mount privileges" — and the thing Sirius currently shells out for (`bsdtar`, `7z`, `blkid`, `mount -o loop`).
* **`bled`** beyond the format list: BusyBox-derived streaming decoders with handle-based I/O (`bled_uncompress_with_handles`), a **size probe** (`bled_size.c`: gzip trailer, xz index, …) that supplies `projected_size` before decoding, and a pluggable write callback — which is what lets `sector_write` re-block the stream.
* **`wimlib`** is vendored (`src/wimlib/`, ~70 files) and called through `wimlib_*U` UTF-8 wrappers; it is also what lets Rufus read WIM XML inside an ISO without mounting (path syntax `image.iso|/sources/install.wim`).
* Legacy and plumbing, skim only: `dos.c`/`dos_locale.c` (FreeDOS/MS-DOS media with locale-derived keyboard/codepage, 1.5 K lines), `src/ms-sys/` (the only place Microsoft/other-vendor boot code lives, covered by PROJECT-STATE), hidden-disk rules for Windows Sandbox/Bitdefender/Dev Drive/Xbox virtual disks (§2; Linux's loop/zram/dm/md/nbd are already excluded by our by-id + removable gate).
* **`ext2fs`**, **`cregex`** (`src/cregex_*.c`, ~900 lines: RH-label matching and dism/oscdimg progress-line parsing in `RunCommandWithProgress` `stdfn.c:798`), **`msapi_utf8.h`** (1,450 lines of UTF-8 shims over the wide Win32 API — Rust gives us this for free), **`darkmode.c`** (1,205 lines, theme lib from @ozone10; Tauri handles theming), **`smart.c`** (SMART passthrough, compiled out).
* **`syslinux.c` + `libinstaller`**: patches `ldlinux.sys` in place using the file's real sector list obtained from the filesystem (FAT via libfat, NTFS via `ntfssect.c`), writes `ldlinux.bss` into the PBR, and has 4 K-sector overrides for `SECTOR_SIZE` (`syslinux.c:44-52`).

## 11. Ten ideas most worth adopting for a cross-platform tool (priority order)

1. **One typed `ImageReport`, built by an in-process ISO reader, gating every destructive step** (rows 1-5). Truncation check, projected size, "image on the target", bootloader/arch inventory, Windows build from WIM XML, exact largest-file size. The same walker for scan and extract, as Rufus does, so detection cannot drift from flashing (our invariants 1 and 3). Unblocks the GUI's inexact Windows-layout dialog (§8 of PROJECT-STATE) and the macOS/Windows backends.
2. **UEFI bootloader revocation + Secure-Boot trust report** (row 6). Everything is portable data; the hash is 60 lines and I have already validated it against `osslsigncode`. Gate it as a warning with Rufus's two-paragraph wording; add the "will fail on machines without the 3rd-party/2023 CA" log lines to the existing UEFI:NTFS caveat. Sign the SBAT/DBX feed, unlike Rufus.
3. **Safety rails Rufus has and we lack** (rows 4, 8-11): refuse the source-on-target case, show other-partition/non-512 warnings from one source of truth (`caveat()` pattern), name the process holding the device, user ignore-list, HDD heuristic as a *warning* only.
4. **Quick capacity (fake-flash) test, plus the full destructive pattern test** (row 15). Block-id stamps at a random in-block offset are the right trick; do it sparsely and first, and offer the hours-long 5-pattern pass as the "Advanced" option with a log file and Abort/Retry/Ignore.
5. **Stale-metadata hygiene** (row 12): wipe head **and tail**, zero each new partition head, wait for the kernel to re-read the table. This is the class of bug behind half of Rufus's "Windows cached the old layout" history (`drive.c:2275`, `ChangeLog.txt:507`).
6. **Save-drive-to-image and zero-drive** (rows 16-17). Small, cross-platform, and a natural companion to a flasher; Rufus already ships VHD/VHDX/FFU/ISO save (`vhd.c:592`), and `dd if=` is the incumbent.
7. **Hash tool that compares** (row 18): all four digests in one pass, accept `SHA256SUMS`/`.sha256` sidecars and pasted values, and say MATCH / MISMATCH — the thing Rufus's ✓ button stops short of.
8. **Signed assets and updates** (rows 23, 38, 39): minisign/ed25519 over manifests, rollback guard, server-time anti-skew, SHA-256 DB with ✓/✗ in the log, VirusTotal monitoring, no packer. Cheap now, painful to retrofit.
9. **Windows 11 customisation parity and verification** (rows 24-26): add the silent-install interlock, CA-2023 loaders, S-mode and `appraiserres.dll`; gate options by WIM build; and **actually test BypassStorage/CPU** — if they are no-ops we must remove them (invariant 13).
10. **ISO mode for Linux with persistence, as an opt-in** (rows 21-23): the one capability that makes Rufus's stick *reusable*. It is large and distro-specific, so start with the data Rufus already collected: the label-rewrite tokens, the `persistent`/`persistence` kernel edits, `persistence.conf` with the trailing newline, the DD-only exception list, and the "recompute `md5sum.txt`" rule.

Honourable mentions: phase-weighted progress and completion cues (row 33), the label sanitiser (row 32), the `res/mbr/msg.S` UEFI-only sector (row 29), copying the five test ISOs (row 41).

## 12. Five things Rufus does that we should deliberately NOT copy

1. **Hidden keyboard "cheat modes" for safety-relevant switches.** Listing USB hard drives, non-USB removable drives, disabling the fake-drive check, ignoring the boot marker, disabling size checks are all undiscoverable Alt-chords, and one logs "you forfeit ANY RIGHT to complain if you lose valuable data!" (`rufus.c:4036,4235-4250`). A tool whose promise is "you can never target the wrong disk" must put these behind a visible Advanced control with a typed confirmation, and record the override in the support log.
2. **Index/heuristic identity as the primary defence.** Rufus targets `\\.\PhysicalDrive<N>` (`N+0x80`), identifies by friendly name, and relies on a 312-line vendor score table that its own header says "NO PROMISE IS MADE" about (`smart.c:~405`). Keep by-id serial targeting (invariant 2) as the gate; use the score only to raise a warning.
3. **Running a downloaded interpreter script to fetch ISOs** (`powershell -ExecutionPolicy Bypass`, temp `.ps1`, named pipe) — it has produced two CVEs already (`ChangeLog.txt:42`) and adds an Authenticode-on-a-script dance. Speak to the vendor API natively and keep the "download in a browser" fallback.
4. **ISO-extract mode as the *recommended default* for hybrid ISOs** (`MSG_275/276`). It is why Rufus carries a per-distro exception list that grows every release (Pop!_OS, Manjaro, openSUSE, Proxmox, Nobara, Kali, Mint LMDE, Tails, Knoppix, Solus, Slax, FreeNAS, Red Hat 8+ `inst.stage2`→`inst.repo`, GRUB 2.06 variants — `iso.c`, `rufus.c:1294-1432`, changelog passim). Keep DD as the default for Linux and treat ISO mode as an explicit opt-in for persistence/mixed use.
5. **The legacy and packer tail**: MS-DOS creation via a `diskcopy.dll` pulled from Microsoft's symbol server, XP/Server 2003 `setupldr.bin` byte patching, the `0x81` BIOS-ID masquerading MBR, KolibriOS/ReactOS/Grub4DOS boot types, `autorun.inf`, UPX-packed executables (and the VirusTotal treadmill they require), the `hogger` console hack, and a registry-key "unofficial version" check (`rufus.c:3865`). Microsoft IP, near-zero users, and attack surface (the diskcopy/oscdimg replacement bugs, `ChangeLog.txt` 4.12).
